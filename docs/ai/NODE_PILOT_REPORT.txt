Document pilot Node and Python hint verification, 2026-11-11

POST /study and POST /study/receipt use X-LAT-IPC and {body,resolved}.
body = {request_id,mode,source_text}
resolved = {actor_id:string}
Valid operational envelopes use HTTP 200 and {status,result,error_code}.
Receipts additionally support pending and missing. Other request errors are
HTTP 400 invalid_request, 409 request_conflict and 503 study_unavailable.
Existing HTTP ingress errors continue to use their existing {error} format.

Node persists a pending SQLite row before dispatch, keyed by actor and UUID
with a hash of mode and excerpt. Exact concurrent duplicates join the flight.
Receipts are read-only. Exact terminal results replay and abandoned pending
rows reopen as unknown. A late response after cancellation cannot update the
receipt. Worker logs include generation metadata only.

Study shares the Tutor slot and LocalModel coordinator with a total 180 s
budget including bounded queue time. Existing tutoring keeps its short
budget. Structured candidate generation has up to 2400 output tokens. It
requests three questions and one lesson of 3–5 sentences for course mode, with citations
constrained to a list of exact Unicode spans selected from the excerpt.
Strict validation rejects malformed, truncated, duplicate-property,
invalid-Unicode, NUL-bearing, out-of-schema, duplicate-question/option and
ungrounded results. A second blind check has up to 512 output tokens inside
the same slot and deadline. The same model sees the excerpt and questions
without proposed keys or explanations. A disagreement, ambiguous or
unsupported question or invalid verifier response fails closed. When all
keys pass, a hint flagged as revealing the answer is replaced with a fixed
neutral cue. No other pack fields are replaced. Worker logs count the hint
replacements without recording their text.
Semantic accuracy still depends on the model and is assessed in live examples.

Ajv 8.17.1 is a runtime dependency with the same pinned dependency graph.
Authorized local Tutor/LocalModel changes are recorded in LOCAL_OVERRIDES.json.
UPSTREAM.json remains the provenance source.

A stored automatic Python assessment can now count as a verified hint event
after checking the local-model source, successful outcome, current rubric,
task and content digest, request UUID, boolean checks, literal answer
evidence and matching score. Hint events keep the original auto_checked
attempt status. Existing human-reviewed grades still qualify. Automatic
feedback starts with 'Автоматическая оценка ИИ.'.
