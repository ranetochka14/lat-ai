# I02.2 — ручная проверка LAT AI в каркасе LAT AI

Откройте `http://127.0.0.1:5173/#/courses`. Тестовый аккаунт **только для этой изолированной БД**: `review@lat-ai.local`, пароль `LatAI-Review-2026!`. Курс «Python · ручная проверка LAT AI» → урок → код задания → вопрос. Полный код прикрепляется автоматически, выделение показывается под редактором. Для начала не нужно выбирать роли, темы или уровни.

Включена ручная проверка взрослыми. Объяснение модели помечается «не проверено». Подсказки выдаются из каталога; резерв и кризисный ответ имеют свои подписи. Код не исполняется. Отправка вопроса не создаёт проверенную попытку и не меняет оценку. Кнопка отправки задания администратору относится к прежнему механизму платформы.

## Запуск и зависимости

На этом ноутбуке подготовлено окружение `../i02-venv/Scripts/python.exe` относительно каркаса. Запуск: `START_AI_REVIEW.cmd`. Он включает уже установленную Qwen 3.5 9B через LM Studio. Загрузка модели выполняется до вопросов, новые веса не скачиваются. Если порты заняты, запуск останавливается и не закрывает чужие процессы; уже работающий стенд можно открыть по ссылке выше.

В PowerShell из корня каркаса:

```powershell
# Без модели: проверка резерва, каталога и безопасности
./tools/start-ai-review.ps1 -NoBrowser
# С установленной моделью: взрослый оператор включает эксперимент
./tools/start-ai-review.ps1 -EnableModel
# Управление уже работающим стендом, только для оператора
./tools/ai-model-control.ps1 -Action status
./tools/ai-model-control.ps1 -Action disable
./tools/ai-model-control.ps1 -Action enable
# L01: безопасно остановить только собственный экземпляр и оставить модель off
./tools/ai-model-control.ps1 -Action retire
```

При переносе нужны Node 24 (проверено на 24.11.1), Python 3.12 и зависимости `integration/ai/requirements-local.txt`. Создайте отдельное окружение, установите этот файл и передайте путь через `-PythonExe`. Ajv нужен только для Node-тестов: `npm --prefix integration/ai ci --ignore-scripts --no-audit --no-fund`. Не запускайте прежний `START-FULL.cmd` для этой задачи: он готовит общий стек документов/поиска.

## Что подключено

- Существующие JWT и Django endpoint `POST /api/v1/tutor/ask/`; заглушка 501 заменена. Проверяются опубликованный курс, урок и связь упражнения. Поля полномочий/истории из браузера отклоняются.
- `GET /api/v1/tutor/context/?course_id=…&lesson_id=…` возвращает доступность упражнений и начальный код. Он не возвращает ключи банка, уровни, внутренние task keys или промпт.
- Приватный Node worker на 127.0.0.1:8372, защищён секретом из `.runtime/i02/ipc-secret.txt`. Прямой доступ браузера и Origin запрещены. Один worker обслуживает все процессы Django; второй владелец журнала блокируется SQLite locking_mode=EXCLUSIVE. После аварии блокировка освобождается ОС, но незавершённые запросы не регенерируются.
- Постоянный журнал ИИ `.runtime/i02/replay.sqlite3` хранит отпечатки и ответы для повторов, выданные подсказки. Вопросы и полный код туда отдельно не пишутся; сохранённый ответ может содержать цитату кода. Это приватные данные replay, не оперативный лог.
- Собственная история подсказок читается внутри секции actor+exercise. Проверенные попытки приходят снимком из Django перед вызовом. Только checked с конечным score в пределах max_score учитываются как проверенная попытка; passed обозначает полный балл, не освоение навыка. Submitted не учитывается. Снимок не обещает учитывать параллельную правку преподавателя после начала запроса.
- Одинаковый actor+request_id присоединяется к запросу или получает сохранённый ответ; изменение тела или mapping — 409. Ответ и событие hint записываются атомарно. После аварии незавершённый ID получает 503, а не повторный вызов модели. Не удаляйте такой ID или lock автоматически по возрасту.
- Основные настройки PostgreSQL сохранены. `config.ai_local` использует отдельную SQLite БД и ограниченный набор URL; документы, поиск и админ-панель здесь выключены. Это не проверка промышленного PostgreSQL-развёртывания.

Mapping создаётся для 2 уроков и 4 точных упражнений, связан с их реальными ID и SHA-256 содержания. Изменение условия отключает старое сопоставление. Другие курсы требуют отдельной проверки и mapping, а не автоматического выбора L1. Начальные упражнения синтетические; проверенные попытки и оценки не создаются.

Статический сервер отдаёт только `index.html` и `assets/`, проверяя путь до и после realpath. Это обязательно для защиты коротких NTFS-имён, приватных ключей и базы. Не копировать `.runtime` на публичный хостинг и не включать её в архив команды.

## Ручная проверка

1. В первом задании выделить `"3" + "2"`, перейти в вопрос, спросить: «Почему + соединяет строки?». Убедиться, что предпросмотр выделения сохранился и ответ ссылается на снимок.
2. Спросить о кавычках и изменить код до прихода ответа. Проверить пометку старого снимка; редактор не блокируется.
3. Нажать «Дай подсказку» несколько раз. Источник — каталог; без проверенной попытки уровень остаётся не выше второго. Полный разбор не включён.
4. Перейти в другой урок во время ответа. Поздний ответ не должен попасть в новый экран.
5. При потере связи «Повторить этот запрос» отправляет прежний ID и прежний снимок. Изменённый вопрос отправляйте основной кнопкой как новый запрос.
6. Проверить кризисную фразу и обычный учебный вопрос. Маршрутизация не является общей гарантией безопасности; S02 с людьми остаётся открытым.

## Проверки и журналы

`npm --prefix integration/ai test`; `npm --prefix integration/ai run check`.
Для Django задать `DJANGO_SETTINGS_MODULE=config.ai_local`, `LAT_AI_TEST=1`, затем `python backend/manage.py test tutor`. Перед обычным запуском удалить `LAT_AI_TEST` из окружения.
`integration/ai/test/live-http.mjs` — отдельный сквозной прогон с синтетическими аккаунтами и живой моделью; по умолчанию в unit tests не входит.

Оперативные журналы — `.runtime/i02/*.log` и `ai-runtime.jsonl`: без JWT, IPC-секрета, вопросов, кода и сырых модельных ответов. Приватный replay хранится отдельно. Синтетические ответы испытаний сохранены в отчёте I02.2 вне репозитория. Резерв не считается успехом модели; короткий живой smoke не заменяет L01, T01, S02, F01 и E01.

Старые v10/v4 и архив I02.1 сохранены. Этот пакет не добавляет RAG, новые веса, оплату, кабинет преподавателя, автоматическое оценивание или исполнение Python.

L01: порядок предварительной загрузки, границы очереди и операторское восстановление описаны в [L01_OPERATIONS.md](L01_OPERATIONS.md). Не удаляйте неизвестные блокировки и не останавливайте общий LM Studio при ошибке.
