# LAT AI — проверка качества автооценки

Область работы — AI-модуль. Оценщик возвращает номера подтверждающих фрагментов; вычисление балла в Django не изменяется. Правильный ответ не распознаётся по заученной строке и не получает принудительный балл.

Известный случай: правильное объяснение `if/else` получало 2 из 3 из-за незачтённого вывода «да» рядом с фразой «else не выполняется». Смысловая ошибка плавающая: сохранённый старый ответ модели её подтверждает, но повтор базовой версии уже принимает этот ответ. Поэтому одних повторов удачного ответа недостаточно для доказательства исправления.

## Воспроизводимые наборы

- `integration/ai/eval/assessment-dev48.json`: 24 прежних и 24 новых авторских примера. Новые примеры зафиксированы до первого изменения оценщика: перефразировки, локальное отрицание, настоящее отрицание, неполные ответы, противоречия, инъекции и соседние рубрики.
- `integration/ai/eval/assessment-repeat10.json`: пять чередующихся пар исходного правильного ответа и ответа с настоящим отрицанием вывода.

Это наборы разработки, использованные при настройке. Они не являются независимой контрольной выборкой, оценкой преподавателя или гарантией точности на произвольных ответах. Повторные прогоны не делают набор независимым.

## Запуск настоящей модели

Нужны Node, установленная Qwen 3.5 9B и работающий LM Studio на `127.0.0.1:1234`, CLI `lms` в PATH. До запуска штатно выгрузить собственную модель стенда: на слабой видеокарте не следует одновременно держать два экземпляра. Чужие модели/процессы не останавливать. Каталог результата должен быть новым; его родитель должен существовать.

Из корня репозитория, подставив путь к нему:

```powershell
node tools/evaluate-assessment.mjs '<путь к репозиторию>' integration/ai/eval/assessment-dev48.json '<путь к репозиторию>'
```

В третьем аргументе укажите новый каталог результата, а не существующий корень репозитория.

Скрипт создаёт свой уникальный экземпляр, вызывает ту же `LocalModel.generate` и `validateAssessment`, сохраняет каждый исходный ответ, ожидаемые/полученные критерии, длительность, `events.jsonl`, `recovery.jsonl` и `summary.json`. В конце выгружает только свой экземпляр с подтверждением. Таймаут 60 секунд — бюджет измерительного инструмента, а не изменение общих лимитов продукта. После неизвестного завершения запроса нельзя повторять POST или удалять lock по возрасту.

Проверять `summary.matched`, список `failed` и событие `retired.proven`. Код завершения сам по себе не означает совпадения всех смысловых оценок. Неудачные результаты сохранять вместе с исходниками/хешами кандидата.

Технические проверки без живой модели: `npm --prefix integration/ai test` и `npm --prefix integration/ai run check`. Во внешней рабочей области (вне этого репозитория) общий сценарий `tools/test-lat-ai.ps1` также запускает существующие Django и baseline core проверки.

## Версия и совместимость

`version: local-assessment-v1` обозначает неизменную схему трёх критериев и ответа. Поле `assessment_revision` отмечает ревизию промпта/настроек. При их изменении обновлять ревизию: Журнал оценки включает весь файл рубрик в отпечаток запроса; запрос с прежними параметрами получит конфликт, без новой генерации и без переписывания старой оценки. Backend/frontend-контракты на этом этапе не расширяются; хранение ревизии в пользовательской истории — отдельное согласование с backend-разработчиком.

Числа и решения текущего эксперимента находятся в рабочей области: `outputs/assessment-fix-2026-11-11/REPORT.txt`, `comparison.json`, `WORKLOG.txt`. Проверка преподавателем и независимая внешняя проверка пока не завершены.
