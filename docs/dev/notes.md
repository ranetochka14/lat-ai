# Решения и ограничения

LAT AI работает как локальный пилот для Windows. Интеграция выросла из прототипа `ranetochka14/lat-ai` на коммите `b4fd637`. Наличие общего репозитория и PR не означает готовности к публичному развёртыванию.

## Что решено

- Django проверяет пользователя и доступ; Node worker имеет приватный IPC и общую блокировку модели; LM Studio обслуживает существующую Qwen3.5-9B. Прямого доступа браузера к worker нет.
- Python оценивается автоматически с записью балла/прогресса. Поддерживаются четыре упражнения, см. [описание оценщика](../specs/ASSESSMENT_EVIDENCE_V3.md); `/assess/receipt` не означает готовое восстановление оценки в Django.
- Личные TXT/PDF/DOCX/PPTX → выбранный фрагмент → мини-курс/MCQ → попытка → баллы и отдельный прогресс. Любые учебные темы разрешены; свободные эссе по всем темам не реализованы. В MCQ модель создаёт ключ, сервер сверяет выбор с ключом.
- Автоматические результаты доступны без обязательного подтверждения преподавателем. При этом независимая проверка качества всё ещё нужна.
- В интерфейсе ровные кликабельные строки; выбранный/верный ответ и объяснение; цитата свёрнута отдельно; Python-отчёт разделён на балл, «Зачтено» и «Нужно уточнить».
- Новая подсказка исключает один неверный вариант с причиной, оставляя три. Объяснение привязано к тексту варианта. При провале проверки подсказка недоступна. Старые материалы не переписываются, попытки сохраняются.
- Учебный пакет из 61 файла импортирован в отдельный тестовый runtime: 2 курса / 50 уроков с самостоятельной практикой, без новых автооценок. См. [описание учебного пакета](../course-pack.md). Инструмент импорта уже входит в main; существующие данные он автоматически не меняет. Платный API, новые веса и RAG не добавлялись. Профиль другого ПК 60/70/80 и эксперимент SDK load/abort не активированы.

## Следующие шаги

Продолжение 12.11: публичные материалы двух школьных курсов включены в исходники; установка в выбранный SQLite runtime выполняется явно с резервной копией и без перезаписи существующих уроков. Исправлены ложный отказ на обычный вопрос о `print` (конфликтующий суффикс интерфейса), отсутствие проверки пакетов из семи вопросов и транспортный обрыв долгой генерации через стандартный Node fetch. Локальный профиль таймаутов теперь поддерживается явно, общие значения сохранены. Работоспособность генерации не подтверждает точность: в живом синтетическом тесте проверка той же моделью пропустила неверное объяснение теоремы Виета и недостаточную цитату.

1. Проверить качество подсказок. Пример SQL прошёл проверку, но на тексте о воде модель назвала таяние противоположностью испарения и превратила «может» в обязательное условие. Проверка той же моделью пропустила ошибку. Сохранить контрпримеры, написать новые вопросы до изменения промпта, отделить примеры для настройки от заранее зафиксированного независимого набора, менять одну переменную. Результаты сохранены в [архиве](https://github.com/ranetochka14/lat-ai/tree/archive).
2. Исправить известные занижения и завышения балла: часть верных ответов получает отказ. Автоматические баллы реализованы, точность всех оценок не доказана.
3. Восстановление незавершённой Python-оценки в Django открыто; unknown POST не повторять. Сверка документной очереди с receipts — отдельный контур.
4. Чистый Windows без зависимостей/модели требует полного испытания. Проверки на машине разработки его не заменяют.
5. Полная визуальная/доступностная приёмка не завершена. Проверены desktop/narrow radio и Down; часть финального browser QA была прервана доступом инструмента.
6. Проверить загрузку и прерывание через SDK на изолированном живом стенде. Этот сценарий не запускался; имитации и запросы только для чтения не подтверждают его работу.

[Результаты проверок](testing.md) отделяют свежие тесты от прошлых испытаний. [Инструкция](runbook.md) описывает запуск без каталогов прежней рабочей области. Исторические пути сохранены в архиве: план — `outputs/AI_ROADMAP.md`, журнал — во внешнем `shag-platform`. Доступ к ним для запуска не нужен. Снимки исследований и отчётов не являются новыми заданиями.

## Именование

| Назначение | Единая форма |
| --- | --- |
| Отображаемое имя | LAT AI |
| Имя с расшифровкой | LAT AI — LEARN AND TALK |
| Slug: файлы, архивы, пакеты, email, ключи | `lat-ai` |
| snake_case: БД и Python-идентификаторы | `lat_ai` |
| Префикс переменных окружения | `LAT_`: `LAT_AI_RUNTIME`, `LAT_FRONTEND_PORT`, `LAT_MODEL_KEY` |
| HTTP-заголовок IPC | `X-LAT-IPC` |
| Синтетический тестовый аккаунт | `review@lat-ai.local` / `LatAI-Review-2026!` |
| Имя пакетного архива (фиксированный формат релиза) | `LAT-AI-Document-Pilot` |
| Отображаемое имя релиза | `LAT AI document pilot …` |
| Значения БД по умолчанию | `lat_ai` (имя, пользователь и пароль локального примера) |

Перед обновлением остановите старый воркер штатным способом и обновите постоянные переменные окружения Windows до префикса `LAT_`; fallback на прежние имена отсутствует. Для существующей БД явно укажите `DB_NAME`, `DB_USER` и `DB_PASSWORD` в локальном `.env`. Переименование исходников не переименовывает БД или пользователей и не изменяет runtime, секреты и квитанции.

Готовый тестовый профиль с `seed.json` сохраняет прежний аккаунт, курс и mapping. Новый профиль получает новые имена; digest курса вычисляется вместе с mapping. Не переименовывайте существующий курс вручную без согласованного обновления mapping. Если в БД нет маркера `seed.json`, подготовка создаёт синтетические записи заново: рядом со старым аккаунтом может появиться второй пользователь и курс; это не миграция существующих данных.

Исторические документы, доказательства проверки, eval JSON, существующие миграции, замороженное ядро и внешние пути происхождения сохраняются дословно. Имена модулей, команды запуска, JS-глобалы и существующие ключи localStorage не переименовываются.

## Учебный интерфейс и настройки

В текущую версию вошли читаемая лекция, явный результат ответа без перерисовки урока, свёрнутые повторные попытки, предупреждение об ошибках ИИ и профильные настройки. Перед генерацией выбираются 5/6/7 вопросов (по умолчанию 6) и подробность материала. Есть новая аддитивная миграция documents/0007; действующую БД перед применением сохранить. Старые материалы и квитанции остаются совместимы. Детали — [спецификация документов](../specs/DOCUMENT_PILOT_SPEC.md#generation-preferences-2026-11-12). Общая модель не включалась; качество и время новых генераций требуют отдельной проверки на живой модели.
