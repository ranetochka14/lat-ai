LAT AI — локальный пилот с документами, 11.11.2026

ПРИМЕЧАНИЕ 12.11.2026: основной запуск теперь START_MAIN.cmd и README.md.
Этот файл описывает отдельный совместимый START_PILOT и его .runtime/pilot.
Для MAIN создавайте администратора с runtime из START_MAIN.cmd -CheckOnly;
см. docs/agent-handoff/RUNBOOK.md. SETUP больше не создаёт pilot-БД заранее.

ЧТО РАБОТАЕТ
Личный документ -> выбранный текст -> мини-курс или тест -> подсказка ->
ответ -> автоматические баллы и прогресс. Поддерживаются любые учебные темы.
Обязательной проверки преподавателем нет. Существующие задания Python
сохраняют автоматическую проверку текстового ответа локальной моделью.

В тестах по документам ИИ создаёт вопросы, четыре варианта, ключ и подсказки.
Сервер сверяет выбор ученика с ключом ИИ и считает балл. Повтор одной и той
же попытки не добавляет баллы. Для каждого вопроса учитывается последний
ответ: исправление меняет результат, но не увеличивает число вопросов.
Пройдено = отвечено на все вопросы; это не гарантия освоения темы.
Ключи ИИ могут быть ошибочны. Проверки формата и цитат не доказывают истинность.
Второй проход той же модели решает вопросы без предложенных ключей; несовпадение
или неоднозначность блокируют набор. Это не независимая экспертиза. Подсказка,
признанная некачественной или раскрывающей ответ, становится недоступной.
Новые подсказки исключают один неверный вариант с объяснением, оставляя три.

БЫСТРЫЙ ЗАПУСК НА WINDOWS
1. Распакуйте исходники в короткий путь, например C:\LAT\document-pilot.
   Не накладывайте их поверх старого рабочего комплекта с личными данными.
2. Нужны Python 3.12 x64, Node.js 22.13+ (проверено с 24.11.1), LM Studio.
   Установите Python/Node обычными официальными установщиками, если их нет.
3. Запустите SETUP_PILOT.cmd. Он создаст .venv, установит requirements.txt
   и зависимости Node. Интернет нужен для библиотек, не для работы ИИ.
   Новые веса/embedding-модель не скачиваются. Полный backend/requirements.txt
   для этого пилота не используется: там есть другой профиль платформы.
4. В LM Studio используйте уже переданный Qwen3.5-9B-Q4_K_M.gguf, model key
   qwen3.5-9b. Если модели ещё нет на ПК, возьмите её из прежнего полного
   Windows-комплекта LAT AI (папка model); импортируйте в LM Studio.
   Этот новый архив исходников не содержит повторную копию весов.
5. Включите локальный сервер LM Studio на 127.0.0.1:1234. Не запускайте
   одновременно второй комплект на тех же портах. START_PILOT.cmd создаёт
   собственный экземпляр существующей модели, не скачивает её.
   Проверьте, что команда lms --version доступна в терминале. При её отсутствии
   настройте официальный CLI LM Studio перед запуском.
6. Запустите START_PILOT.cmd. Оставьте окно запуска открытым.
   Откройте http://127.0.0.1:5173/#/documents
   API: http://127.0.0.1:8000/api/v1
   Django admin: http://127.0.0.1:8000/admin/
7. Для локальной демонстрации есть review@lat-ai.local / LatAI-Review-2026!
   Это обычный тестовый аккаунт, не администратор. Можно создать свой через сайт.
   Для Django admin выполните CREATE_PILOT_ADMIN.cmd и задайте свой пароль.
8. Ctrl+C в окне запуска останавливает только процессы этого пилота и пытается
   выгрузить только собственный экземпляр модели. Общий LM Studio не выключается.

КАК ПРОЙТИ СЦЕНАРИЙ
Откройте «Документы», загрузите TXT/PDF/DOCX/PPTX, проверьте извлечённый текст.
Для примера используйте tools/demo-materials/pilot-history.txt,
pilot-biology.txt или pilot-math.txt.
Выберите диапазон и «Мини-курс» либо «Тест». Генерация выполняется в фоне;
можно вернуться к списку. Статус сохраняется при обновлении страницы.
После готовности откройте материал, прочитайте уроки, выберите вариант
ответа и нажмите «Проверить ответ». «Подсказка» доступна без преподавателя.
Перед вопросами также показан весь выбранный учебный фрагмент: краткий урок
ИИ может не перечислить все необходимые факты. Фрагмент можно свернуть.
Правильность, объяснение, цитата, баллы и прогресс появляются автоматически.
Прогресс этих личных мини-курсов находится в разделе документов/материала;
публичные Python-курсы и их прежний прогресс остаются отдельными.

ГРАНИЦЫ ПЕРВОЙ ВЕРСИИ
- Файл до 20 МиБ, извлечённый текст до 200000 символов.
- Одна генерация охватывает явно выбранные 100–6000 символов; длинный
  документ не считается целиком обработанным. Ничего молча не обрезается.
- Мини-курс: 1–3 коротких урока; тест: 3–6 вопросов с одним вариантом ответа.
  Свободные эссе по произвольным темам пока не оцениваются.
- PDF должен содержать текст; OCR сканов/картинок, сложные формулы и диаграммы
  не распознаются. Результат извлечения нужно смотреть в предпросмотре.
- Локальная генерация может занять до трёх минут; при занятой модели короткий
  тьютор может сообщить о недоступности. Его прежний бюджет не увеличен.
- По одному активному материалу на пользователя, общая очередь до восьми.
- При ошибке/неизвестном результате нет выдуманного урока или балла.
- Документы, оригиналы, материалы и попытки доступны только владельцу.
  Всё локально: внешние API, embedding/RAG и передача документов в сеть отсутствуют.
- Это локальный пилот на loopback, не публичный сервер и не готовый интернет-хостинг.

ДАННЫЕ, ЛОГИ, ВОССТАНОВЛЕНИЕ
Отдельная база, личные файлы, секреты и квитанции лежат в .runtime/pilot.
Каждый запуск пишет логи в .runtime/pilot/logs/<дата-время>.
Базу/секреты/lock-файлы не удаляйте при сбое. Старые .runtime/i02 и БД
прежнего комплекта этот запуск не переносит и не перезаписывает.
После перезапуска очередь сверяет уже отправленные задания с квитанциями
ИИ-worker. Неизвестный POST автоматически не повторяется.
Если модель попала в quarantine, сохраните логи; не удаляйте lock по возрасту.
Команды оператора (из корня, с тем же runtime/портами):
  .venv\Scripts\python.exe -B tools/pilot.py model status
  .venv\Scripts\python.exe -B tools/pilot.py model retire
  .venv\Scripts\python.exe -B tools/pilot.py model enable
Retire применим только к экземпляру, которым владеет этот worker.
После падения самого worker старую чужую блокировку он не присваивает.
Для такого случая требуется разбор журнала и подтверждение остановки
точного экземпляра; автоматической очистки блокировки нет.

НЕСТАНДАРТНЫЕ ПОРТЫ И ДИАГНОСТИКА
  .venv\Scripts\python.exe -B tools/pilot.py --api-port 8001 --site-port 5174 --worker-port 8373 --enable-model run
В интерфейсе откройте «Сервер платформы» и укажите
http://127.0.0.1:8001/api/v1. После смены адреса войдите заново.
Сам по себе другой порт сайта НЕ меняет сохранённый адрес API.
Занятые порты дают явную ошибку; чужие процессы не завершаются.
Проверки без модели:
  .venv\Scripts\python.exe -B tools/pilot.py manage check
  npm --prefix integration/ai test
  node --test tests/document-pilot-frontend.test.cjs
Нативная библиотека может блокироваться политикой Windows App Control:
не отключайте защиту. Установите зависимости в обычную .venv через SETUP.
Наличие скопированного Python не доказывает, что все его DLL разрешены на новом ПК.

ЧТО ПЕРЕДАВАТЬ
Исходники с этим README, requirements.txt, CMD-запусками и MANIFEST.json.
Не передавайте .runtime, личные документы, базы, IPC-секреты или журнал с
реальными учебными ответами. Существующий файл весов передаётся отдельно.
История разработки и результаты проверки: docs/ai/*PILOT* и отчёт рядом
с архивом. Проверка на чистом ПК тестировщика остаётся отдельным шагом.
